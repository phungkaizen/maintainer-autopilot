# Safety model

The project prioritizes recoverability and traceability over maximum autonomy.

## Invariants

- Only one active writer may own a workspace.
- A new task cannot replace a non-checkpointed task.
- Review failure and deterministic gate failure enter `REPAIR_REQUIRED`.
- Repair continues the existing task ID and increments its attempt counter.
- Promotion is unavailable before `READY_TO_PROMOTE`.
- Automatic merge is disabled by default.
- Stale-lock recovery is explicit and operator-controlled.

## Agent permissions

The default Codex implementation command uses `workspace-write`, while the default review command uses `read-only`. `danger-full-access` is not generated by default.

Any configured agent command can still be destructive. Run the project in a Git repository, use branches/worktrees, protect production credentials, and review the resulting diff.

## Threats not solved in v0.1

- A malicious repository script executed by a deterministic gate.
- A compromised external agent CLI.
- Distributed races across multiple copies of the same repository.
- Supply-chain risk in project dependencies or GitHub Actions.
- Prompt injection from untrusted issue text.
